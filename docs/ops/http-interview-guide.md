# HTTP 全面面试题

> 本文档覆盖 HTTP 协议的核心知识点，包含概念理解、协议细节、实践应用等方面的面试题及详细解答。

---

## 一、HTTP 基础概念

### 1. 什么是 HTTP？它的主要特点是什么？

**参考答案：**

HTTP（Hypertext Transfer Protocol）是一种用于分布式、协作式超媒体信息系统的应用层协议。

**主要特点：**

1. **无状态**：服务器不保留客户端的状态信息，每次请求都是独立的
2. **无连接**：请求完成后立即断开连接（HTTP/1.1 引入持久连接）
3. **简单**：协议结构简单，易于实现和扩展
4. **灵活**：支持多种数据类型（HTML、JSON、图片等）
5. **明文传输**：数据以明文形式传输（HTTPS 解决此问题）
6. **客户端-服务器模型**：客户端发起请求，服务器响应

**HTTP 的工作流程：**
1. 客户端建立 TCP 连接
2. 客户端发送 HTTP 请求
3. 服务器处理请求并返回响应
4. 关闭连接（或复用连接）

---

### 2. HTTP 和 HTTPS 有什么区别？

**参考答案：**

| 特性 | HTTP | HTTPS |
|------|------|-------|
| **安全性** | 明文传输，不安全 | 加密传输，安全 |
| **端口** | 80 | 443 |
| **加密方式** | 无 | SSL/TLS 加密 |
| **证书** | 不需要 | 需要 CA 证书 |
| **性能** | 较快 | 较慢（需要加密解密） |
| **地址栏标识** | 无特殊标识 | 显示锁图标 |
| **SEO** | 一般 | 搜索引擎更信任 |

**HTTPS 的工作流程：**
1. 客户端发起 HTTPS 请求
2. 服务器返回 SSL/TLS 证书
3. 客户端验证证书有效性
4. 客户端生成对称密钥并使用服务器公钥加密发送
5. 服务器使用私钥解密获取对称密钥
6. 双方使用对称密钥进行加密通信

---

### 3. HTTP 协议的发展历程是怎样的？

**参考答案：**

| 版本 | 年份 | 主要特性 |
|------|------|----------|
| **HTTP/0.9** | 1991 | 仅支持 GET 方法，纯文本传输 |
| **HTTP/1.0** | 1996 | 支持多种方法（GET、POST、HEAD），引入 HTTP 头，支持缓存 |
| **HTTP/1.1** | 1999 | 持久连接（Connection: keep-alive），管道化请求，分块传输，Host 头，缓存控制 |
| **HTTP/2** | 2015 | 多路复用，头部压缩，服务器推送，优先级 |
| **HTTP/3** | 2022 | 基于 QUIC 协议，更快的连接建立，更好的拥塞控制 |

## 二、HTTP 请求方法

### 4. HTTP 常见的请求方法有哪些？各自的用途是什么？

**参考答案：**

| 方法 | 用途 | 是否幂等 | 是否安全 |
|------|------|----------|----------|
| **GET** | 获取资源 | 是 | 是 |
| **POST** | 创建资源 | 否 | 否 |
| **PUT** | 更新资源（替换） | 是 | 否 |
| **PATCH** | 更新资源（部分修改） | 否 | 否 |
| **DELETE** | 删除资源 | 是 | 否 |
| **HEAD** | 获取资源头部信息 | 是 | 是 |
| **OPTIONS** | 获取服务器支持的方法 | 是 | 是 |
| **CONNECT** | 建立隧道连接 | - | - |
| **TRACE** | 回显请求（用于调试） | 是 | 是 |

**关键区别：**

- **GET vs POST**：
  - GET：请求参数在 URL 中，长度有限制，可缓存
  - POST：请求参数在请求体中，长度无限制，不可缓存

- **PUT vs PATCH**：
  - PUT：替换整个资源
  - PATCH：部分修改资源

---

### 5. GET 和 POST 的区别是什么？

**参考答案：**

| 特性 | GET | POST |
|------|------|------|
| **请求体** | 无 | 有 |
| **参数位置** | URL 中 | 请求体中 |
| **长度限制** | 有（取决于浏览器和服务器） | 无 |
| **缓存** | 可缓存 | 不可缓存 |
| **幂等性** | 是 | 否 |
| **安全性** | 较低（参数暴露在 URL） | 较高 |
| **编码类型** | application/x-www-form-urlencoded | application/x-www-form-urlencoded 或 multipart/form-data |

**使用场景：**
- **GET**：查询数据、获取资源
- **POST**：提交表单、创建资源、上传文件

## 三、HTTP 状态码

### 6. HTTP 状态码分为几类？各自代表什么含义？

**参考答案：**

HTTP 状态码分为五类，用三位数字表示：

| 类别 | 范围 | 含义 |
|------|------|------|
| **1xx** | 100-199 | 信息性状态码，请求已接收，继续处理 |
| **2xx** | 200-299 | 成功状态码，请求已成功处理 |
| **3xx** | 300-399 | 重定向状态码，需要进一步操作 |
| **4xx** | 400-499 | 客户端错误状态码，请求有问题 |
| **5xx** | 500-599 | 服务器错误状态码，服务器处理失败 |

---

### 7. 常见的 HTTP 状态码有哪些？各自代表什么？

**参考答案：**

**2xx 成功：**
- **200 OK**：请求成功
- **201 Created**：资源创建成功
- **204 No Content**：请求成功但无响应体
- **206 Partial Content**：部分内容（用于断点续传）

**3xx 重定向：**
- **301 Moved Permanently**：永久重定向
- **302 Found**：临时重定向
- **304 Not Modified**：资源未修改（缓存命中）
- **307 Temporary Redirect**：临时重定向（保持请求方法）
- **308 Permanent Redirect**：永久重定向（保持请求方法）

**4xx 客户端错误：**
- **400 Bad Request**：请求语法错误
- **401 Unauthorized**：未授权（需要登录）
- **403 Forbidden**：禁止访问（权限不足）
- **404 Not Found**：资源未找到
- **405 Method Not Allowed**：请求方法不允许
- **408 Request Timeout**：请求超时
- **409 Conflict**：资源冲突

**5xx 服务器错误：**
- **500 Internal Server Error**：服务器内部错误
- **502 Bad Gateway**：网关错误
- **503 Service Unavailable**：服务不可用
- **504 Gateway Timeout**：网关超时

## 四、HTTP 头信息

### 8. 常见的 HTTP 请求头有哪些？

**参考答案：**

**通用头：**
- `Host`：请求的主机名和端口
- `Connection`：连接管理（keep-alive / close）
- `Date`：请求发送时间

**请求头：**
- `Accept`：客户端可接受的响应内容类型
- `Accept-Encoding`：客户端可接受的编码方式（gzip、deflate）
- `Accept-Language`：客户端语言偏好
- `Authorization`：身份认证信息
- `Cache-Control`：缓存控制指令
- `Content-Type`：请求体的内容类型
- `Content-Length`：请求体的长度
- `Cookie`：客户端存储的 Cookie
- `Referer`：请求来源页面
- `User-Agent`：客户端信息（浏览器、设备等）

**响应头：**
- `Content-Type`：响应体的内容类型
- `Content-Length`：响应体的长度
- `Content-Encoding`：响应体的编码方式
- `Content-Language`：响应内容的语言
- `Server`：服务器信息
- `Set-Cookie`：设置 Cookie
- `Location`：重定向地址
- `Cache-Control`：缓存控制指令
- `ETag`：资源的实体标签（用于缓存验证）
- `Last-Modified`：资源最后修改时间

---

### 9. Cache-Control 有哪些常用指令？

**参考答案：**

**请求指令：**
- `no-cache`：需要向服务器验证后才能使用缓存
- `no-store`：不使用缓存，每次都向服务器请求
- `max-age=<seconds>`：缓存的最大有效时间
- `max-stale=<seconds>`：允许使用过期缓存
- `min-fresh=<seconds>`：要求缓存至少保持新鲜指定秒数

**响应指令：**
- `public`：响应可被任何缓存缓存
- `private`：响应只能被客户端缓存
- `no-cache`：需要向服务器验证后才能使用缓存
- `no-store`：不缓存响应
- `max-age=<seconds>`：缓存的最大有效时间
- `must-revalidate`：缓存过期后必须向服务器验证
- `proxy-revalidate`：代理缓存过期后必须向服务器验证
- `s-maxage=<seconds>`：共享缓存的最大有效时间

### 10. 什么是跨域？如何解决跨域问题？

**参考答案：**

**跨域**是指浏览器出于安全考虑，限制从一个源加载的文档或脚本与另一个源的资源进行交互。

**同源策略**：协议、域名、端口都相同才是同源。

**常见的跨域解决方案：**

1. **CORS（Cross-Origin Resource Sharing）**
   - 服务器设置响应头 `Access-Control-Allow-Origin`
   - 支持预检请求（OPTIONS）
   - 支持携带凭证（withCredentials）

2. **代理服务器**
   - 在同域服务器上设置代理
   - 将请求转发到目标服务器
   - 如：Nginx 反向代理

3. **JSONP**
   - 利用 `<script>` 标签不受同源策略限制
   - 只支持 GET 请求
   - 需要服务器配合返回回调函数

4. **WebSocket**
   - WebSocket 协议不受同源策略限制
   - 建立持久连接

5. **PostMessage**
   - 用于 iframe 之间的跨域通信

## 五、HTTP 缓存

### 11. HTTP 缓存的原理是什么？

**参考答案：**

HTTP 缓存是指浏览器或代理服务器将已获取的资源副本存储起来，以便在后续请求时直接使用，减少网络请求，提升性能。

**缓存类型：**

1. **强缓存**：
   - 通过 `Expires` 或 `Cache-Control: max-age` 控制
   - 浏览器直接使用缓存，不向服务器发送请求

2. **协商缓存**：
   - 通过 `Last-Modified / If-Modified-Since` 或 `ETag / If-None-Match` 控制
   - 浏览器向服务器发送请求验证缓存是否有效
   - 若有效返回 304 Not Modified，否则返回新资源

**缓存流程图：**
```
浏览器发起请求
    ↓
检查强缓存是否有效？
    ├─ 是 → 使用缓存
    └─ 否 → 向服务器发送请求
                ↓
        服务器验证协商缓存
            ├─ 有效 → 返回 304，使用缓存
            └─ 无效 → 返回 200，更新缓存
```

---

### 12. Expires 和 Cache-Control: max-age 有什么区别？

**参考答案：**

| 特性 | Expires | Cache-Control: max-age |
|------|---------|------------------------|
| **类型** | 响应头 | 响应头 |
| **时间格式** | 绝对时间（如 `Mon, 20 Jul 2024 10:00:00 GMT`） | 相对时间（如 `max-age=3600`） |
| **优先级** | 较低 | 较高（覆盖 Expires） |
| **时区依赖** | 依赖客户端时间 | 不依赖客户端时间 |
| **兼容性** | HTTP/1.0 | HTTP/1.1 |

**使用建议：**
- 同时设置两者以保证兼容性
- 优先使用 `Cache-Control: max-age`

---

### 13. ETag 和 Last-Modified 有什么区别？

**参考答案：**

| 特性 | ETag | Last-Modified |
|------|------|---------------|
| **类型** | 实体标签（哈希值） | 最后修改时间 |
| **精度** | 高（精确到字节级别） | 低（精确到秒级别） |
| **生成方式** | 服务器根据资源内容计算 | 服务器记录的修改时间 |
| **优先级** | 较高 | 较低（ETag 优先） |
| **适用场景** | 动态内容、频繁更新的资源 | 静态文件 |

**工作流程：**
- **第一次请求**：服务器返回 `ETag: "abc123"` 和 `Last-Modified: Mon, 20 Jul 2024 10:00:00 GMT`
- **第二次请求**：浏览器发送 `If-None-Match: "abc123"` 和 `If-Modified-Since: Mon, 20 Jul 2024 10:00:00 GMT`
- **服务器验证**：
  - 若 ETag 匹配，返回 304
  - 若 ETag 不匹配，返回 200 和新资源

## 六、HTTP/2 和 HTTP/3

### 14. HTTP/2 相比 HTTP/1.1 有哪些改进？

**参考答案：**

HTTP/2 相比 HTTP/1.1 有以下核心改进：

1. **多路复用**：
   - 单个 TCP 连接上可以同时发送多个请求和响应
   - 消除了 HTTP/1.1 的队头阻塞问题

2. **头部压缩**：
   - 使用 HPACK 算法压缩 HTTP 头部
   - 减少重复头部的传输量

3. **服务器推送**：
   - 服务器可以主动向客户端推送资源
   - 提前发送客户端可能需要的资源

4. **请求优先级**：
   - 客户端可以为请求设置优先级
   - 服务器根据优先级决定响应顺序

5. **二进制协议**：
   - HTTP/2 使用二进制格式传输数据
   - 更高效的解析和处理

---

### 15. HTTP/3 相比 HTTP/2 有哪些改进？

**参考答案：**

HTTP/3 相比 HTTP/2 有以下核心改进：

1. **基于 QUIC 协议**：
   - HTTP/3 使用 QUIC 协议而非 TCP
   - QUIC 是基于 UDP 的传输层协议

2. **更快的连接建立**：
   - QUIC 支持 0-RTT 或 1-RTT 连接建立
   - 比 TCP 的 3-RTT 更快

3. **更好的拥塞控制**：
   - QUIC 实现了更先进的拥塞控制算法
   - 支持多种拥塞控制策略

4. **连接迁移**：
   - QUIC 支持连接迁移
   - 网络切换时无需重新建立连接

5. **内置 TLS 1.3**：
   - QUIC 内置加密
   - 无需额外的 TLS 握手

## 七、HTTPS

### 16. HTTPS 的工作流程是怎样的？

**参考答案：**

HTTPS 的工作流程分为以下几个阶段：

1. **客户端发起请求**：
   - 客户端向服务器发送 HTTPS 请求
   - 服务器端口通常是 443

2. **服务器返回证书**：
   - 服务器返回 SSL/TLS 证书
   - 证书包含服务器公钥、证书颁发机构等信息

3. **客户端验证证书**：
   - 客户端验证证书的有效性
   - 检查证书是否过期、是否由可信 CA 颁发

4. **客户端生成对称密钥**：
   - 客户端生成随机对称密钥
   - 使用服务器公钥加密对称密钥

5. **服务器解密获取密钥**：
   - 服务器使用私钥解密获取对称密钥
   - 双方现在拥有相同的对称密钥

6. **加密通信**：
   - 双方使用对称密钥进行加密通信
   - 后续请求和响应都使用对称密钥加密

---

### 17. SSL 和 TLS 有什么区别？

**参考答案：**

| 特性 | SSL | TLS |
|------|-----|-----|
| **全称** | Secure Sockets Layer | Transport Layer Security |
| **关系** | TLS 是 SSL 的升级版 | SSL 的后继者 |
| **版本** | SSL 2.0、SSL 3.0 | TLS 1.0、1.1、1.2、1.3 |
| **安全性** | 较低（存在安全漏洞） | 较高（修复了 SSL 的漏洞） |
| **兼容性** | 较旧的系统可能仍在使用 | 现代浏览器普遍支持 |
| **握手协议** | SSL 握手协议 | TLS 握手协议（优化版） |

**TLS 1.3 的改进：**
- 更快的握手（1-RTT 或 0-RTT）
- 更强的加密算法
- 移除不安全的加密套件
- 更好的前向保密性

## 八、实践应用

### 18. 如何优化 HTTP 请求性能？

**参考答案：**

1. **减少请求数量**：
   - 合并 CSS 和 JavaScript 文件
   - 使用 CSS Sprites 合并图片
   - 使用 Webpack/Rollup 等工具进行代码分割

2. **使用 CDN**：
   - 将静态资源部署到 CDN
   - 利用 CDN 的边缘节点加速

3. **启用压缩**：
   - 启用 gzip 或 Brotli 压缩
   - 减少传输数据量

4. **合理使用缓存**：
   - 设置合适的 Cache-Control 策略
   - 使用 ETag 和 Last-Modified 进行协商缓存

5. **使用 HTTP/2**：
   - 利用多路复用减少队头阻塞
   - 利用服务器推送提前加载资源

6. **优化图片**：
   - 使用合适的图片格式（WebP、AVIF）
   - 设置合适的图片尺寸
   - 使用响应式图片

7. **减少重定向**：
   - 避免不必要的重定向
   - 使用 301/308 进行永久重定向

### 19. 如何实现断点续传？

**参考答案：**

断点续传是指在下载过程中，如果连接中断，可以从中断的位置继续下载，而不需要重新下载整个文件。

**实现步骤：**

1. **客户端请求**：
   - 客户端发送带有 `Range` 请求头的请求
   - 例如：`Range: bytes=1024-`（表示从第 1024 字节开始）

2. **服务器响应**：
   - 服务器检查 `Range` 请求头
   - 如果支持断点续传，返回 `206 Partial Content` 状态码
   - 返回 `Content-Range` 响应头，如 `Content-Range: bytes 1024-2047/10000`
   - 返回对应范围的文件内容

3. **客户端处理**：
   - 客户端接收部分内容
   - 将内容追加到已下载的文件中
   - 如果下载中断，下次请求继续从断点位置开始

**关键头信息：**
- `Range`：请求范围（如 `bytes=start-end`）
- `Content-Range`：响应范围（如 `bytes start-end/total`）
- `Accept-Ranges`：服务器支持的范围单位（如 `bytes`）

### 20. 如何实现文件上传进度显示？

**参考答案：**

**方法一：使用 XMLHttpRequest**

```javascript
const xhr = new XMLHttpRequest();
const formData = new FormData();
formData.append('file', file);

xhr.open('POST', '/upload');

xhr.upload.addEventListener('progress', (event) => {
  if (event.lengthComputable) {
    const percent = (event.loaded / event.total) * 100;
    console.log(`Upload progress: ${percent}%`);
  }
});

xhr.send(formData);
```

**方法二：使用 Fetch API + ReadableStream**

```javascript
const response = await fetch('/upload', {
  method: 'POST',
  body: formData,
});

const reader = response.body.getReader();
let received = 0;

while (true) {
  const { done, value } = await reader.read();
  if (done) break;
  received += value.length;
  console.log(`Received: ${received}`);
}
```

**方法三：使用第三方库**
- axios 的 `onUploadProgress` 回调
- react-dropzone 等上传组件库

## 九、安全相关

### 21. HTTP 常见的安全问题有哪些？

**参考答案：**

1. **HTTPS 相关**：
   - 未使用 HTTPS，数据明文传输
   - SSL/TLS 证书过期或无效
   - 使用不安全的加密套件

2. **CSRF（跨站请求伪造）**：
   - 攻击者诱导用户执行非预期操作
   - 防护：使用 CSRF Token、验证 Referer、使用 SameSite Cookie

3. **XSS（跨站脚本攻击）**：
   - 攻击者注入恶意脚本
   - 防护：输入过滤、输出转义、使用 CSP（内容安全策略）

4. **点击劫持**：
   - 攻击者通过 iframe 覆盖页面
   - 防护：使用 X-Frame-Options 头

5. **SQL 注入**：
   - 攻击者通过输入恶意 SQL
   - 防护：使用参数化查询、ORM 框架

6. **Cookie 安全**：
   - Cookie 被窃取或篡改
   - 防护：设置 HttpOnly、Secure、SameSite 属性

---

### 22. 如何保护 Cookie 的安全？

**参考答案：**

设置 Cookie 时可以添加以下属性来增强安全性：

1. **HttpOnly**：
   - 防止 JavaScript 访问 Cookie
   - 防止 XSS 攻击窃取 Cookie

2. **Secure**：
   - 仅在 HTTPS 连接时发送 Cookie
   - 防止 Cookie 在 HTTP 连接中被窃取

3. **SameSite**：
   - 控制 Cookie 是否在跨站请求中发送
   - `Strict`：仅在同源请求中发送
   - `Lax`：在 GET 请求中可以发送
   - `None`：允许跨站发送（需要配合 Secure）

4. **Max-Age / Expires**：
   - 设置 Cookie 的过期时间
   - 避免 Cookie 永久有效

5. **Domain**：
   - 限制 Cookie 发送的域名
   - 防止 Cookie 被其他域名获取

6. **Path**：
   - 限制 Cookie 发送的路径
   - 避免 Cookie 在不必要的路径中发送

## 十、总结

### 23. HTTP 协议的核心设计原则是什么？

**参考答案：**

1. **无状态**：服务器不保留客户端状态，每次请求独立
2. **无连接**：请求完成后断开连接（HTTP/1.1 引入持久连接）
3. **简单性**：协议结构简单，易于实现和扩展
4. **灵活性**：支持多种数据类型和传输方式
5. **可扩展性**：通过 HTTP 头和方法扩展协议功能
6. **可靠性**：基于 TCP 传输，保证数据可靠到达

### 24. 为什么 HTTP/2 比 HTTP/1.1 更快？

**参考答案：**

HTTP/2 比 HTTP/1.1 更快主要有以下原因：

1. **多路复用**：单个 TCP 连接上可以同时处理多个请求和响应，消除了队头阻塞问题
2. **头部压缩**：使用 HPACK 算法压缩 HTTP 头部，减少传输量
3. **服务器推送**：服务器可以主动推送资源，减少请求次数
4. **请求优先级**：客户端可以为请求设置优先级，服务器优先处理重要请求
5. **二进制协议**：使用二进制格式传输，解析更高效

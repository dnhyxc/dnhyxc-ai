## 8.1 系统架构

### 8.1.1 双层认证防护

```
┌─────────────────────────────────────────┐
│           路由守卫（前端静态检查）          │
│  Layout 层 token 存在性检查              │
│  + publicPath 白名单                      │
├─────────────────────────────────────────┤
│           HTTP 拦截器（实时 401 收敛）     │
│  HttpClient 拦截器捕获 401               │
│  → notifyUnauthorized                    │
│  → 清理全局状态 → 跳转登录                │
├─────────────────────────────────────────┤
│           后端鉴权                        │
│  JWT 中间件                              │
│  角色/权限守卫                            │
└─────────────────────────────────────────┘
```

### 8.1.2 关键模块

| 模块 | 职责 | 关键文件 |
|------|------|----------|
| 路由守卫 | 检查 token、白名单路由 | `router/index.tsx` |

## 8.3 HTTP 401 拦截

### 8.3.1 HttpClient 实现

```typescript
// service/httpClient.ts
const httpClient = axios.create({
  baseURL: import.meta.env.VITE_API_BASE,
  timeout: 30000,
});

httpClient.interceptors.request.use((config) => {
  const token = localStorage.getItem('token');
  if (token && !config.headers?.['silent']) {
    config.headers.Authorization = `Bearer ${token}`;
  }
  return config;
});

httpClient.interceptors.response.use(
  (response) => response,
  (error) => {
    if (error.response?.status === 401) {
      const isSilent = error.config.headers?.['silent'];

      if (!isSilent) {
        // 清理全局状态
        resetUserState();

        // 跳转到登录页
        localStorage.removeItem('token');
        window.location.href = '/login';
      }
    }
    return Promise.reject(error);
  },
);

export function silentRequest(config: AxiosRequestConfig): Promise {
  return httpClient({
    ...config,
    headers: { ...config.headers, silent: true },
  });
}
```

## 8.4 SecretInput 组件

### 8.4.1 实现细节

```typescript
// components/SecretInput.tsx
interface SecretInputProps {
  value?: string;
  onChange?: (value: string) => void;
  placeholder?: string;
  type?: 'password' | 'apiKey';
  disabled?: boolean;
}

export function SecretInput({
  value: controlledValue,
  onChange,
  placeholder,
  type = 'password',
  disabled,
}: SecretInputProps) {
  const [internalValue, setInternalValue] = useState(controlledValue || '');
  const [show, setShow] = useState(false);
  const isControlled = controlledValue !== undefined;

  const value = isControlled ? controlledValue! : internalValue;

  const handleChange = (e: React.ChangeEvent<HTMLInputElement>) => {
    const newValue = e.target.value;
    if (isControlled) {
      onChange?.(newValue);
    } else {
      setInternalValue(newValue);
      onChange?.(newValue);
    }
  };

  return (
    <div className="relative">
      <input
        type={show ? 'text' : type}
        value={value}
        onChange={handleChange}
        placeholder={placeholder}
        disabled={disabled}
        tabIndex={value ? undefined : -1}
        className="pr-10"
      />
      <button
        type="button"
        onClick={() => setShow(!show)}
        disabled={!value}
        className="absolute right-2 top-1/2 -translate-y-1/2"
        tabIndex={-1}
      >
        {show ? <EyeOffIcon /> : <EyeIcon />}
      </button>
    </div>
  );
}
```

```typescript
// service/pay.service.ts
async createCheckoutSession(dto: CreateCheckoutSessionDto, userId: string) {
  const plan = MEMBERSHIP_PLANS.find(p => p.code === dto.membershipPlan);
  if (!plan) throw new BadRequestException('无效的套餐');

  const session = await this.stripe.checkout.sessions.create({
    ui_mode: 'embedded',
    redirect_on_completion: 'never',
    line_items: [{
      price: plan.stripePriceId,
      quantity: 1,
    }],
    mode: 'payment',
    metadata: {
      userId,
      membershipDays: plan.days,
      membershipPlan: plan.code,
    },
    payment_method_types: ['card'],
  });

  return {
    sessionId: session.id,
    clientSecret: session.client_secret,
  };
}
```

### 8.7.2 双通道开通（幂等）

```typescript
// service/membership.service.ts
async grantMembershipFromCheckoutSession(sessionId: string) {
  // 幂等检查
  const redisKey = `pay:membership:grant:${sessionId}`;
  const isNew = await this.redis.setnx(redisKey, '1', 'EX', 3600);
  if (!isNew) {
    // 已处理过，直接返回
    return this.getMembershipBySession(sessionId);
  }

  const session = await this.stripe.checkout.sessions.retrieve(sessionId);
  const { userId, membershipDays, membershipPlan } = session.metadata as any;

  return this.grantAfterPayment(userId, parseInt(membershipDays), membershipPlan);
}

async grantAfterPayment(userId: string, days: number, plan: string) {
  const user = await this.userRepo.findOne(userId);

  const now = new Date();
  let expiresAt: Date;

  if (user.memberExpiresAt && user.memberExpiresAt > now) {
    // 在原到期日上叠加
    expiresAt = new Date(user.memberExpiresAt.getTime() + days * 24 * 60 * 60 * 1000);
  } else {
    // 从现在起算
    expiresAt = new Date(now.getTime() + days * 24 * 60 * 60 * 1000);
  }

  user.isMember = true;
  user.memberExpiresAt = expiresAt;
  user.membershipPlan = plan;
  await this.userRepo.save(user);

  return {
    isMember: true,
    memberExpiresAt: expiresAt.toISOString(),
    membershipPlan: plan,
  };
}
```

```typescript
// hooks/useMembershipActive.ts
export function useMembershipActive(): MembershipInfo {
  const user = useUserStore();

  // 优先看 memberExpiresAt 时间戳
  const isActive = useMemo(() => {
    if (!user.memberExpiresAt) return false;
    const expiresAt = new Date(user.memberExpiresAt);
    return expiresAt > new Date();
  }, [user.memberExpiresAt]);

  // 到期后 lazy sync
  useEffect(() => {
    if (user.isMember && !isActive) {
      syncMembershipIfExpired();
    }
  }, [user.isMember, isActive]);

  return {
    isActive,
    expiresAt: user.memberExpiresAt,
    plan: user.membershipPlan,
  };
}
```

## 8.9 超级管理员与高危写接口

### 8.9.1 为什么要独立鉴权

某些写接口能直接修改全站功能模块清单（例如插件 registry 的 `PUT /upload/remotes/:filename` 接口），如果只校验「已登录」，等于任意注册用户都可以改写上架列表，接管侧栏入口、iframe 来源、信任级别等关键配置。因此高危写接口需要在 JWT 之上叠加**超级管理员**角色校验。

### 8.9.2 前后端角色真值表对齐

后端：`UserService.userHasSuperAdminRole(userId)` 以 roles 关联表为准——任一角色 `id === 1` 或 `name === '超级管理员'` 即通过。

前端：`checkIsSuperAdmin(userInfo)` 完全沿用同一套键，并额外兼容 `name === 'Super Admin'`（双语兜底）。前后端判定函数必须**同真同假**，避免「前端显示按钮但后端 403」或「前端不显示但后端其实可写」的错配。

### 8.9.3 接口三层防御

| 层 | 机制 | 响应码与语义 |
|---|---|---|
| L1 | NestJS `JwtGuard` 守卫：缺失或非法 Token 在进入 Controller 前拦截 | 401（Guard 标准返回） |
| L2 | Controller 内读 `req.user?.userId`：JWT 解析成功但 payload 缺 userId 主动抛异常 | 401 `未授权` |
| L3 | `userHasSuperAdminRole(userId)` 落库查 roles 关联表：非管理员明确拒绝 | 403 `需要超级管理员权限` |

Controller 中的前置守卫示例：

```typescript
import {
  Controller, Put, Param, Body, Req, UseGuards, UseInterceptors,
  ForbiddenException, UnauthorizedException,
} from '@nestjs/common';
import type { Request } from 'express';
import { JwtGuard } from '../../guards/jwt.guard';
import { ResponseInterceptor } from '../../interceptors/response.interceptor';
import { UserService } from '../user/user.service';

type AuthedRequest = Request & { user?: { userId?: number } };
type PutRemoteBody = { content?: string };

@Controller('upload')
@UseInterceptors(ResponseInterceptor)
@UseGuards(JwtGuard)
export class UploadRemotesWriteController {
  // NestJS 构造器注入 UserService；首次显式自定义构造器
  constructor(private readonly userService: UserService) {}

  @Put('remotes/:filename')
  async putRemote(
    @Req() req: AuthedRequest,
    @Param('filename') filename: string,
    @Body() body: PutRemoteBody,
  ) {
    // L2：Guard 通过后 userId 仍可能缺失（如 JWT payload 被改写 / 版本错位）
    const userId = req.user?.userId;
    if (userId == null) throw new UnauthorizedException('未授权');
    // L3：落库查 roles 关联；不是管理员就 403
    if (!(await this.userService.userHasSuperAdminRole(userId))) {
      throw new ForbiddenException('需要超级管理员权限');
    }
    // 后续：文件名/路径穿越校验、JSON 解析、结构校验、写盘……
  }
}
```

### 8.9.4 前端「隐藏入口 + 后端兜底」双保险

前端的「编辑配置」等高级入口使用 `useIsSuperAdmin()` Hook：
- 管理员：渲染按钮，可跳转到 registry 编辑页；
- 普通用户：DOM 里无节点（通过 `{isSuperAdmin ? <Button /> : null}` 条件块）。

Hook 会订阅原生 `storage` 事件和业务自定义 `userInfoChanged` 事件，登出、换号、多 Tab 同步登录态时自动重算。但**前端隐藏永远不等于安全**——后端三层防御必须独立存在；即使用户手动拼 URL 进入保存页，提交时仍会被 403 拦回。

### 8.9.5 回归建议

- **403 主路径**：非管理员调 `PUT /upload/remotes/plugins-registry.json`，返回体含「需要超级管理员权限」、磁盘文件无改动；
- **401 主路径**：JWT payload 去除 userId，调 PUT 返回「未授权」；
- **200 正路径**：管理员保存 plugins-registry.json，`/remotes/plugins-registry.json` 内容更新；
- **UI 体验**：非管理员看不到「编辑配置」入口；管理员登出 → 入口消失；普通用户切号为管理员 → 入口自动出现。

### A 关键技术决策

- **策略形状不变**：听写仍 ahead=5 TTS 预取；标注仍 cacheOnly → 首题单标 + 其余 batch。
- **Abort 真取消**：切题 bump 世代，旧 speech/annotate 随 `AbortSignal` 取消，不写缓存、不 Toast。
- **TTS 不单开 Redis**：路径索引与配额字节复用全局 Cache；过期用磁盘 mtime + 游标分批删。
- **旁路超时不改连接语义**：业务层 1.5s race；Keyv / Bull `enableOfflineQueue` 保持改前，避免伤验证码与 Worker。

### 阅读建议

1. 先读 **Agent 业务消息分表方案**，理解整体架构（`AgentTurnMemory` 端口 + 四套表路由）。
2. 再读 **Skill 系统后端** 和 **Agent Skill 强制加载与 SSE**，理解 Skill 从存储到注入模型的全链路。
3. 然后读 **知识库助手接入 Agent** 和 **Skill 前端**，理解前端如何使用 Skill。
4. 若手测侧栏：再读 **Skill 侧栏朗读与会话切换**（朗读生命周期 + `mode:skillId` 分桶，修正「开合库断播 / 试跑生成串台」）。
5. 再读 **文档级快捷键**，理解保存/新建快捷键如何从页面内提升为应用级。
6. 最后读 **Share 分表路由与 Assistant 改造** 和 **数据库迁移**，了解配套改造。

### 关键技术决策

- **消息分表而非分区**：英语学习 / Skill 试跑 / 知识库助手各有独立表，历史列表互不污染。
- **`AgentTurnMemory` 端口**：AgentService 不关心消息落哪张表，运行时按 `memorySource` 选实现。
- **Skill 三重注入**：系统提示硬约束 + 用户前缀钉死 + 预置 `apply_skill` 工具消息，确保模型必执行 Skill。
- **SSE error 用 next 而非 error**：Nest SSE 中途 `subscriber.error` 常丢帧，统一用 `next({ type: 'error' })` + `complete`。
- **appliedSkills 双写**：流开始立即写快照（防崩溃丢失），流结束再带正文更新同一行；`assistant_messages` 和 `skill_try_messages` 均有此列。
- **文档级快捷键**：Layout 全局监听 keydown（捕获阶段），页面通过 `bindDocumentShortcutHandlers` 注册回调，模块级 `handlers` 变量实现跨组件通信。
- **Skill 侧栏 scope**：`` `${mode}:${skillId|__draft__}` `` 分桶；朗读 hook 挂在 `SkillsPage`，避免 `ResizablePanelGroup` remount 断播。

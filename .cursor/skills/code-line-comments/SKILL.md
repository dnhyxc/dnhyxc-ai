# 源码逐行注释（code-line-comments）

## 目标

在**指定源码文件或符号**中，为**每一行源码**在其**正上方**追加一行**详细**中文讲解注释。

**注释是帮助读者理解代码，不是完成覆盖率 KPI。** 每条讲解必须对应**该行在真实运行中的角色**；读不懂就先读上下文，**禁止**用模板、脚本或语法标签凑数。

---

## 语义真实（与「只增注释」并列的硬要求）

1. **信息增益测试**（写每条注释前必过）
   - 自问：删掉这条注释，读者会**少知道什么**？
   - 若答案只是「这是 if / 这是闭合括号 / 这是 Bot 导入」→ **不合格**，重写或合并到段首讲解。
2. **先读懂再写**
   - 先通读目标符号完整定义（声明 → 闭合），弄清数据从哪来、到哪去、分支在解决什么问题。
   - **禁止**未读上下游就按行号/正则批量插入注释；**禁止**用脚本模板替代人工理解（批量生成几乎必然注水）。
3. **写「做了什么、为什么」，不写「语法是什么」**
   - 合格：`// 侧栏打开期间记下引用 CFI，分栏 resize 结束后滚回视口`
   - 不合格：`// 条件判断分支`、`// 局部绑定`、`// 闭合语句块`、`// 具名导入项 Bot`
4. **与源码已有注释**
   - 仓库自带 `//`、`JSDoc` **保留原位**。
   - 若下行已有清晰说明：上一行可写**补充上下文**（调用方、边界、与相邻分支关系），**禁止**同义复述；无需重复时可写「见下行注释」并只补上下游。
5. **质量优先于机械 100%**
   - 若某行**单独注释**只能重复上一行或标识符拼读，**不要**为达标而注水。
   - 可在**段首**（如 `import {`、`useEffect(() => {`、`}, [`）上方用**一条**注释说明整段意图；段内无独立语义的行（import 单个符号、纯 `}`、deps 中与段首重复的项）**可豁免**，须在交付说明中列出区间。
   - 有独立运行时语义的行（赋值、API 调用、分支条件、return 值）**仍须**逐行讲解，不得合并糊弄。

---

## 绝对硬约束（违反即失败）

1. **只增注释，不改代码**
   - **禁止**修改、删除、移动、重排任何源码行（含空格、缩进、引号、分号、括号、换行）。
   - **禁止**「顺手」重构、重命名、改 import、改类型、加/删逻辑、修 lint、格式化。
   - **禁止**把已有行内/块注释挪到上方后删掉原注释（可保留原注释，上方再补讲解行）。
2. **注释在上方**
   - 每条讲解占**源码上一行**；**禁止**用行尾 inline 注释替代（仓库原有行尾注释保留不动）。
3. **100% 覆盖（在有信息增益的前提下）**
   - 除 §豁免 外，**每个物理源码行**正上一行须是**有语义价值**的讲解；禁止只注释「关键行」或 diff 行。
   - **JSX / HTML 标记节点行**不在范围内（见 §6）。
   - 段内可合并讲解的行见上文「质量优先于机械 100%」，须在交付中说明豁免区间。
4. **中文**
   - 讲解统一简体中文；英文术语可保留，首次出现可加括号释义。
5. **禁止前缀**
   - 不用 `讲解：`、`说明：`、`注：` 开头。
6. **不对 HTML / JSX 节点加注释**
   - **禁止**在 JSX/TSX 或 HTML 模板中，为**标记节点行**插入上方讲解注释。
   - **标记节点行**包括：`<Tag>` / `</Tag>` / `<Tag />`、仅含 JSX 属性的一行、JSX 子文本纯展示行、HTML 元素开闭标签。
   - **仍须注释**：`import`、类型、hook、回调、逻辑语句、`return (` 等非标记行；组件 `return` 块内只注释 TS 逻辑，不注释 JSX 树。

与用户明确要求冲突时：**以「不改代码」为最高优先级**；宁可少注释几行并说明范围，也不改一行源码。

---

## 何时启用

- 用户 @ 文件/目录并要求「逐行注释」「每行上面加注释」。
- 用户限定函数、组件、hook、类、模块范围。
- 用户强调 **只加注释、不能改代码**。

**不启用**（改用其它 skill）：

- 写 docs 围栏代码块 → `implementation-doc-from-diff`
- 代码审查 / 修 bug / 重构 → `code-review` 或普通 agent

## 工作流

### 1) 锁定范围

确认：

| 项                           | 说明                                       |
| ---------------------------- | ------------------------------------------ |
| 路径                         | 单文件 / 多文件 / 符号名                   |
| 语言                         | 决定注释语法（见下表）                     |
| 是否含测试、生成代码、vendor | 默认跳过 `node_modules`、`.min.`、lockfile |

无范围时：先读文件，向用户确认符号边界，**不要**整文件盲目注释（超大文件先问）。

### 2) 读代码再写

- 先通读目标符号**完整定义**（声明 → 闭合），理解数据流与控制流。
- 注释写**该行在业务/运行时中的含义**，不是重复标识符拼读，也不是语法类别标签。
- 超大文件：按符号分段处理；**每段写前重读该段**，避免后半段注释与真实逻辑脱节。

### 3) 逐行追加注释

自上而下扫描；对每一**源码行**在其上一行插入讲解注释。

**注释语法**

| 语言                | 语法      |
| ------------------- | --------- |
| TS / JS / TSX / JSX | `// …`    |
| Python / Shell      | `# …`     |
| CSS                 | `/* … */` |
| SQL                 | `-- …`    |

### 4) 落盘前自检（§1.2 扫描）

对每个目标块自上而下：

1. 空行（仅空白）→ 跳过。
2. 已是讲解注释行（`//` / `#` / `/*`）→ 跳过。
3. 否则为源码行 → **上一行必须是讲解注释**；否则补全。

额外核对（高频漏注）：

- `return {` 内**每个有独立行为的属性行**（含 `onCopy:` 等回调属性）；纯语法闭合行可随段首合并
- 箭头函数**体内每一行**（**不含** JSX 标记节点行，见 §6）
- `useMemo` / `useCallback` 的 **deps**：须在 `[` 上方或每个依赖行说明**为何**重算（触发场景），禁止只写「依赖：变量名」
- 每个 `}`、`});`：若单独成行，须说明**闭合的是哪一层**（如「结束 ensureQuoteCfiInViewport 回调」），禁止泛写「闭合语句块」

### 5) 交付前 diff 审查

```bash
git diff -- <paths>
```

**合格 diff**：仅 `+` 以 `//` / `#` / `/*` 开头的行（及因插入注释产生的上下文行号偏移，无 `-` 删改源码）。

**不合格**：任何 `-` 删掉或改了源码正文 → **回滚并重做**。

---

## 「详细」标准

每条注释至少说明其一（最好多条）：

- 该行**执行什么**、读写哪些变量 / props / state
- 在**控制流**中的角色（分支、return、循环、异常）——须具体到**判的是什么、为何 return**
- 与**上下游**衔接（数据从哪来、传给谁）
- **非显而易见**的业务或平台细节

**禁止**空洞套话、语法标签、标识符拼读作为唯一内容：

| 不合格 | 应改为 |
| ------------- | --------------------------------------------------------- |
| `// 条件判断` / `// 条件判断分支` | `// cluster 为空时不渲染引用操作条` |
| `// 获取变量` | `// 从 epubNavRef 取 rendition，未挂载则为 undefined` |
| `// 结束函数` / `// 闭合语句块` | `// 结束 applyClosedLayout，供 effect 与 layout 兜底复用` |
| `// 局部绑定` | `// 合并后的 targetCfi，供 scroll 与 PopBar 定位共用` |
| `// 具名导入项 Bot` | （段首）`// lucide：顶栏助手/翻页/目录/PDF 缩放图标` |
| `// 返回调用方所需值` | `// 返回 EPUB 顶栏 trailing 节点，非 epub 时为 null` |
| `// 模块 import 语句` | `// 高亮 CRUD：划线持久化与列表刷新` |
| `// 依赖：bookId` | `// bookId 变则重新绑定本书高亮/想法请求` |
| `// state xxx：见命名` | 读代码后写清该 state 在阅读流程中的具体用途 |

**import 块**：在 `import {` 或首行 import 上方说明**在本文件中的用途**；单个符号行若无额外信息，可随段豁免（见「语义真实 §5」）。

**deps 数组**：说明每个依赖变化时会**重新执行什么行为**，而非罗列变量名。

---

## 豁免（可不加上方讲解的行）

- 源码**纯空行**（仅空白）。
- **本次新增的讲解注释行**本身。
- **JSX / HTML 标记节点行**（见硬约束 §6）：不对 `<div>`、`<Component />`、`prop={x}` 等标记行加注释。
- **段内无独立语义行**（见「语义真实 §5」）：如 import 列表中的单个符号、段首已说明过的 deps 重复项、仅配对用的 `}`——须在交付中列出区间。
- 用户**明确排除**的行（须在回复中列出）。

源码中的空行：**上方可不注释**；空行**下方**若紧跟源码，该源码行仍须上一行注释。

---

## 与仓库已有注释

- 源码自带 `//`、`/* */`、JSDoc **保留在原位**。
- 讲解在源码**上方额外一行**；与下行重复时**补上下文**，或「见下行注释」+ 上下游，**禁止**同义复述。

## 示例（TS，仅展示注释插入方式）

**改动前**

```typescript
const applyClosedLayout = useCallback(() => {
	assistantPanelRef.current?.collapse();
	panelGroupRef.current?.setLayout(CLOSED_LAYOUT);
}, []);
```

**改动后**（源码字符完全一致，仅上方增行）

```typescript
// 收起右侧分栏并让左侧占满，供 sidePanelOpen 关闭与 layout 兜底复用
const applyClosedLayout = useCallback(() => {
	// collapse 可折叠 assistant panel，释放百分比给 reader
	assistantPanelRef.current?.collapse();
	// 命令式将 layout 设为 reader 100%、assistant 0%
	panelGroupRef.current?.setLayout(CLOSED_LAYOUT);
	// 无 deps：回调仅通过 ref 读 panel API，引用稳定
}, []);
```

## JSX / HTML 示例（标记行不加注释）

**仍注释**（逻辑行）：

```tsx
// 侧栏有书且 MK 助手打开时渲染助手面板
if (assistantOpen) {
	// 以下 JSX 树为标记节点，各行不加讲解注释
	return <EbookAssistant bookId={book.id} onInputChange={setAssistantInput} />;
}
```

**不加注释**：`<EbookAssistant`、`bookId=…`、`/>`、`</div>` 等标记节点行。

## 输出给用户

完成后简要说明：

1. 注释了哪些路径 / 符号（行号范围）。
2. 覆盖情况：**有语义价值的行**是否均已讲解；**不含** JSX/HTML 标记节点行；若有段内合并/豁免，列出区间与原因。
3. 确认 **git diff 仅新增注释行**。
4. 若文件此前存在注水注释，是否已按本 skill 重写或移除。

---

## 反模式（禁止）

- 用正则/脚本按行号批量生成注释，未读代码语义。
- 每行套用「条件判断 / 局部绑定 / 闭合块 / 返回调用方所需值」等万能模板。
- import 成员、deps 元素逐行拼读变量名而无「变化时发生什么」。
- 为凑 100% 对自解释单行重复 `if (!x) return` 的含义而无新信息（可合并到段首）。

## Agent 自检清单

- [ ] diff 中**无任何**源码正文修改？
- [ ] 每条注释通过**信息增益测试**（删掉会少知道具体行为/原因）？
- [ ] **未**使用语法标签、标识符拼读、脚本批量模板？
- [ ] 目标范围内**有独立语义的行**均有讲解（**不含** JSX/HTML 标记节点行）？
- [ ] **未**对 JSX/HTML 开闭标签、属性行、纯展示子节点加注释？
- [ ] 回调体内、return 对象行为属性、deps **触发原因**均已说明（非仅变量名）？
- [ ] 无 `讲解：` / `说明：` 前缀？
- [ ] 段内合并/豁免已在回复中列出？
- [ ] 未顺手重构、未改 import、未修无关 lint？

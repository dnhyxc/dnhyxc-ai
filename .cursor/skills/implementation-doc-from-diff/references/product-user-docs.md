## 1. 硬性约束：正文不得出现文件路径

在 **`项目指南.md`** 与 **`项目更新信息.md`** 的正文（含列表项、示例说明）中：

| 禁止 | 允许 |
|------|------|
| 仓库相对/绝对路径（`apps/...`、`docs/...`、`wiki/...`、`packages/...`） | 产品模块名（知识库、对话、英语学习） |
| 文件名、目录名、`.ts`/`.tsx` 路径 | 路由 **路径片段**（如 `/chat`、`/update-info`）— 面向用户的外链/书签 |
| 「见 xxx.md」「见 § 某专题文」类开发索引 | 功能名、按钮名、设置项名（与 UI 一致） |
| 环境变量名、`Info.plist` 等工程配置名（除非产品设置页已暴露同名文案） | 技术术语 + 括号中文（如 SSE、RAG、ATS）— 与现有文风一致 |

**专题实现文**（`<WIKI_ROOT>/knowledge/...` 等）仍须保留路径与代码来源标注；产品向两份文档单独遵守上表。

## 2. `项目更新信息.md` 格式

- 文首保留产品级导语（强调可感知能力、**正文不列工程路径**）。
- 按 **`## N. 章节标题`** 分域（与现有风格一致）；新能力归入**已有章节**优先，确实无合适章节再追加新 `##` 节。
- 每条能力一条 bullet，推荐形态：

```markdown
- **能力名**：用户能感知到的一句话结果。（更新：YYYY-MM-DD）
```

- 日期用当天；同类优化可合并为一条，勿刷屏。

---

## 3. `项目指南.md` 格式

- 教程向：「怎么用」；按产品模块分章。
- 新功能优先插入**已有章节**合适位置；整章新增须有清晰 `##` 标题。
- **禁止**在教程正文中写「实现见 wiki/…」「源码在 apps/…」；深度实现留给开发索引（仅保留一句「克隆仓库后查阅开发文档总索引」，**不写** `wiki/` / `docs/` 下具体文件名）。
- 与 `项目更新信息.md` **姊妹维护**：教程写「怎么用」，更新信息写「新增/优化了什么」；避免大段复制粘贴。

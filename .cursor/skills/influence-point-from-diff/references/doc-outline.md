## 结论摘要表写法

- 「是否影响原有功能」列只用：**否**、**是**、**有条件变化**、**低（增强）** 等固定措辞。
- 「说明」列一句说清：不变原因 / 变化点 / 触发条件。
- 行粒度：用户可独立理解的产品能力或模块，不要一行笼统写「电子书」。

## 影响点矩阵写法

- **模块/场景**：用产品语言（PopBar 听当前、用户划线 sync），必要时括号符号名。
- **影响等级**：无 < 低 < 中 < 高；「无」须说明代码路径未触达。
- **分析**：写**机制**（谁调谁、哪层 DOM、何时 sync），避免「可能有问题」式空话。

# 微服务架构实现方案及具体实现步骤

> 适用范围：将 `apps/backend` 现有 NestJS 单体应用演进为微服务架构。  
> 编写基线：当前仓库 `apps/backend/src/app.module.ts` 注册的 25 个业务模块、`docker-compose.yml`（MySQL db/db1 + Qdrant）、`deploy.backend.json`（单机 PM2 部署）。  
> 落地原则：**绞杀者模式（Strangler Fig）渐进迁移**，每阶段可独立上线、可回滚，不允许一次性推倒重写。

---

## 1. 目标与范围

### 1.1 目标
- 按业务领域将单体拆分为若干**独立部署、独立数据库**的微服务。
- 引入 **API 网关**统一入口，屏蔽内部服务拓扑。
- 引入**异步事件总线**（Redis Streams / BullMQ）解耦跨服务写操作。
- 建立**统一鉴权、配置中心、链路追踪、集中日志**的公共能力。
- 容器化部署，逐步从 `docker-compose` 过渡到 Kubernetes 编排。

### 1.2 范围
- ✅ 服务拆分边界划分（领域驱动，映射到现有 NestJS 模块）
- ✅ API 网关与服务间通信（同步 HTTP + 异步事件）
- ✅ 数据库拆分与迁移策略
- ✅ 公共能力下沉（鉴权 / 配置 / 日志 / 追踪 / 监控）
- ✅ 分阶段落地步骤（M0–M4，每步含验收清单）
- ✅ 具体代码改造示例（NestJS 微服务 Transport）
- ✅ 部署与运维（docker-compose → k8s）

### 1.3 非目标
- 不在第一阶段引入 Service Mesh（Istio/Linkerd），留作 M5 演进项。
- 不强制使用 gRPC（先用 NestJS 内置 TCP/Redis Transport，后续对高频调用切 gRPC）。
- 不在本方案中设计前端改造（Tauri/React 调用入口由网关统一承接，前端无需感知拆分）。

### 2.3 当前痛点（驱动拆分的理由）
1. **单库膨胀**：所有领域共享一个 MySQL 实例，表数量已 40+（见 `migrations/`），故障爆炸半径大。
2. **部署耦合**：一次任何模块改动都要整体 `pnpm build` → 全量重启，无法独立发布。
3. **资源隔离缺失**：AI 流式（Chat/Agent/EbookAssistant）与 CRUD（User/Knowledge）抢占同一进程内存。
4. **横向扩展困难**：无法只对「知识库检索」或「流式对话」做独立扩容。

## 3. 微服务拆分策略（领域驱动）

### 3.1 拆分原则
1. **按业务能力而非技术分层**：一个微服务 = 一个限界上下文。
2. **数据所有权独立**：每个服务独占自己的表集合，不直连他人数据库。
3. **同步调用最小化**：跨服务读用 HTTP/RPC，跨服务写优先走事件。
4. **高内聚低耦合**：同一事务边界的表必须在同一服务内。

### 4.2 API 网关（api-gateway）

**职责**：
1. **路由分发**：按路径前缀转发到后端微服务。
2. **鉴权前置**：统一校验 JWT，将 `userId`/`username`/`roles` 以 Header 透传给下游。
3. **限流**：继承现有 `express-rate-limit`（300 req/min）。
4. **SSE 透传**：对 `/api/chat/*`、`/api/knowledge/qa/ask` 等流式接口做管道透传，不缓冲。
5. **Swagger 聚合**：合并各服务的 OpenAPI 文档到 `/api-docs`。

**路由规则**：

| 前缀 | 转发目标 |
|------|---------|
| `/api/auth` `/api/user` `/api/roles` `/api/menus` `/api/logs` | identity-svc |
| `/api/knowledge` `/api/knowledge/qa` | knowledge-svc |
| `/api/chat` `/api/agent` `/api/assistant` `/api/web-search` `/api/llm-config` | ai-chat-svc |
| `/api/ebook` `/api/ebook-assistant` | ebook-svc |
| `/api/english-learning` `/api/learning-notes` | english-svc |
| `/api/upload` `/api/mail` `/api/ocr` `/api/prompt` `/api/share` `/api/pay` `/api/plugin-prefs` `/api/speech-transcription` | platform-svc |
| `/images` `/files` `/remotes`（静态） | 本地静态中间件（保留） |

**网关启动示例**（`apps/backend/src/apps/api-gateway/main.ts`）：

```ts
import { NestFactory } from '@nestjs/core';
import { AppModule } from './app.module';
import { AllExceptionFilter } from '../../filters/all-exception-filter';
import { WINSTON_MODULE_NEST_PROVIDER } from 'nest-winston';
import helmet from 'helmet';
import rateLimit from 'express-rate-limit';
import { JwtGuard } from './guards/jwt-proxy.guard';
import { Reflector } from '@nestjs/core';

async function bootstrap() {
  const app = await NestFactory.create(AppModule);
  app.setGlobalPrefix('api');
  app.use(helmet({ crossOriginResourcePolicy: { policy: 'cross-origin' } }));
  app.use(rateLimit({ windowMs: 60_000, max: 300 }));
  // 全局 JWT 校验，校验通过后把 user 信息写入 header 透传
  const reflector = app.get(Reflector);
  app.useGlobalGuards(new JwtProxyGuard(reflector));
  const logger = app.get(WINSTON_MODULE_NEST_PROVIDER);
  app.useGlobalFilters(new AllExceptionFilter(logger, app.get(HttpAdapterHost)));
  await app.listen(9112);
}
```

### 4.3 服务间通信

#### 4.3.1 同步通信（HTTP）
- 网关 → 微服务：**HTTP REST**（保持前端调用路径不变）。
- 微服务 → 微服务：NestJS `@nestjs/microservices` + **TCP Transport**（内部网络，低延迟）；对外仍暴露 HTTP Controller。

**示例：ai-chat-svc 调用 knowledge-svc 检索**（`ai-chat-svc/src/proxies/knowledge.proxy.ts`）：

```ts
import { Inject, Injectable } from '@nestjs/common';
import { ClientProxy } from '@nestjs/microservices';
import { KNOWLEDGE_SERVICE } from '../constants/inject-tokens';

@Injectable()
export class KnowledgeProxy {
  constructor(@Inject(KNOWLEDGE_SERVICE) private client: ClientProxy) {}

  // 同步检索知识证据（pattern-based）
  search(query: string, userId: number) {
    // send 返回 Observable，首项即结果
    return this.client.send({ cmd: 'knowledge_search' }, { query, userId });
  }

  // 异步通知失效缓存
  emitKnowledgeUpdated(knowledgeId: number) {
    return this.client.emit('knowledge.updated', { knowledgeId });
  }
}
```

#### 4.3.2 异步通信（事件总线）
- **载体**：复用现有 Redis，使用 BullMQ 的 `Queue` + `QueueEvents` 或 NestJS Redis Microservice Transport。
- **事件命名规范**：`{domain}.{action}`，如 `identity.user_registered`、`platform.payment_succeeded`。
- **消费幂等**：消费者用 `eventId` 去重（Redis SETNX，TTL 24h）。

**事件发布示例**（`platform-svc` 支付成功后通知 identity）：

```ts
import { Controller } from '@nestjs/common';
import { EventPattern, Payload } from '@nestjs/microservices';

@Controller()
export class PaymentEventConsumer {
  constructor(private identityService: IdentityProxy) {}

  @EventPattern('platform.payment_succeeded')
  async handlePayment(@Payload() data: { userId: number; membershipType: string; eventId: string }) {
    // 幂等检查
    const acquired = await this.redis.set(`evt:${data.eventId}`, '1', 'EX', 86400, 'NX');
    if (!acquired) return; // 已处理

    // 回调 identity-svc 写会员权益（HTTP，走 JwtProxyGuard 内部 token）
    await this.identityService.grantMembership(data.userId, data.membershipType);
  }
}
```

### 4.4 配置中心
- **M1–M2 阶段**：沿用 NestJS `ConfigModule` + `.env.{NODE_ENV}`，每个服务一份 `.env`。
- **M3 阶段**：引入 **Consul / Nacos** 作为配置中心，`@nestjs/microservices` 支持 ConfigModule 动态拉取。
- **密钥**：Stripe / COS / 各 LLM API Key 保留在环境变量，不进配置中心明文存储。

## 5. 数据架构

### 5.1 数据库拆分方案

| 服务 | 新库名 | 来源表（从 `dnhyxc_ai_db` 迁出） |
|------|--------|-------------------------------|
| identity-svc | `dnhyxc_identity` | user, profile, roles, menus, user_wechat, logs |
| knowledge-svc | `dnhyxc_knowledge` | knowledge, knowledge_trash, knowledge_category |
| ai-chat-svc | `dnhyxc_ai_chat` | chat, session, chat_message, attachments, agent_*, assistant_*, llm_runtime_config |
| ebook-svc | `dnhyxc_ebook` | ebook_book, ebook_category, ebook_chapter, ebook_highlight, ebook_thought, ebook_progress, ebook_user_prefs, ebook_share, ebook_auth, ebook_assistant_* |
| english-svc | `dnhyxc_english` | english_*, learning_note* |
| platform-svc | `dnhyxc_platform` | ocr, prompt, share, membership_payment_grant, plugin_user_prefs, minimax_tts_user_config, wechat_epub* |

> Qdrant 由 knowledge-svc 独占访问，其他服务不直连。

### 5.2 数据迁移策略（分表迁移）

1. **建新库**：在每个微服务的 `migrations/` 中新增 `CreateDatabase` 迁移。
2. **结构迁移**：用现有 `npm run sql:safe` 导出结构，按表归属拆分到各库。
3. **数据迁移**：双写过渡（绞杀者模式）——
   - M2 阶段：微服务写入新库，同时通过事件同步回旧库（兼容期）。
   - M3 阶段：读流量切到新库，旧库设只读。
   - 切换完成后下线旧库。
4. **外键处理**：删除跨库外键，改为应用层引用（如 `chat.userId` 仅存 ID，不 JOIN）。

### 5.3 分布式事务（Saga 模式）
- ** Choreography Saga**：通过事件链协调，无中心协调器。
- 示例：支付 → 会员授权
  ```
  platform-svc: PaymentSucceeded(userId, type) ──► event bus
  identity-svc: consume → grantMembership() ──► MembershipGranted(userId) ──► event bus
  platform-svc: consume → updateOrderFulfilled()
  ```
- **补偿**：每步需定义补偿动作（如 `grantMembership` 失败 → 发 `MembershipGrantFailed` → platform-svc 回滚订单状态）。

## 6. 公共能力下沉

### 6.1 鉴权统一
- JWT 签发与校验逻辑从 `AuthModule` 下沉到 **identity-svc**。
- 网关持有 JWT 公钥（或共享 `SECRET`），完成校验后把 `x-user-id` / `x-user-name` / `x-user-roles` Header 透传。
- 下游服务通过中间件解析 Header 重建 `req.user`，不重复查库。

**下游服务统一中间件**（`shared/middleware/user-context.middleware.ts`）：

```ts
import { Injectable, NestMiddleware } from '@nestjs/common';
import { Request, Response, NextFunction } from 'express';

@Injectable()
export class UserContextMiddleware implements NestMiddleware {
  use(req: Request, res: Response, next: NextFunction) {
    // 网关透传的 header
    const userId = req.headers['x-user-id'];
    const username = req.headers['x-user-name'];
    const roles = req.headers['x-user-roles']; // 逗号分隔
    if (userId) {
      req.user = {
        id: Number(userId),
        username: username as string,
        roles: roles ? (roles as string).split(',') : [],
      };
    }
    next();
  }
}
```

### 6.2 链路追踪
- 引入 **OpenTelemetry** + **Jaeger**。
- 每个微服务在 `main.ts` 启动前注入 `@opentelemetry/api` 的 `NodeTracerProvider`。
- 跨服务调用自动传播 `traceparent`（NestJS Microservice Transport 已支持注入 Carrier）。

### 6.3 集中日志
- 沿用 `nest-winston`，日志输出 JSON 格式，带 `service` / `traceId` / `spanId` 字段。
- 每个服务用 Filebeat 或 `winston` 直推 **Loki / ELK**。

### 6.4 监控指标
- `@nestjs/terminus` 健康检查端点 `/health`。
- `prom-client` 暴露 `/metrics`，Prometheus 抓取。

## 7. 分阶段落地步骤

> 每阶段输出：代码改动 + docker-compose 更新 + 验收清单。  
> **铁律**：任意阶段失败可回滚到上一阶段，前端调用路径全程不变。

### M0：准备阶段（不拆分，搭基建）

**目标**：建立 monorepo 多应用骨架，保持单体运行。

**步骤**：
1. 在 `apps/backend/src/` 下建 `apps/` 目录，为后续各微服务预留位置。
2. 抽取 **shared 公共包**（`apps/backend/src/shared/`）：DTO、装饰器、拦截器、过滤器、枚举、工具函数。
3. `app.module.ts` 改为「聚合各模块」的过渡态，无行为变化。
4. docker-compose 增加 `redis` 服务（当前本地缺失，生产已有）。

**docker-compose.yml 增量**：

```yaml
services:
  redis:
    image: redis:7.4
    container_name: dnhyxc_ai_redis
    restart: always
```

4. **网关代理 Controller 示例**：

```ts
import { All, Controller, Req, Res } from '@nestjs/common';
import { Request, Response } from 'express';
import { HttpService } from '@nestjs/axios';
import { firstValueFrom } from 'rxjs';

@Controller('api')
export class ProxyController {
  constructor(private http: HttpService) {}

  // 通配转发到 identity-svc
  @All('auth/*path')
  async proxyAuth(@Req() req: Request, @Res() res: Response) {
    const path = req.params.path;
    const url = `http://identity-svc:9201/api/auth/${path}`;
    // 透传 x-user-* header
    const headers = this.forwardHeaders(req);
    const resp = await firstValueFrom(
      this.http.request({ method: req.method as any, url, data: req.body, headers, params: req.query })
    );
    res.status(resp.status).json(resp.data);
  }

  private forwardHeaders(req: Request) {
    return {
      'x-user-id': req.headers['x-user-id'] as string,
      'x-user-name': req.headers['x-user-name'] as string,
      'x-user-roles': req.headers['x-user-roles'] as string,
      'content-type': req.headers['content-type'] as string,
    };
  }
}
```

```ts
@All('chat/*path')
async proxyChatStream(@Req() req: Request, @Res() res: Response) {
  const url = `http://ai-chat-svc:9203/api/chat/${req.params.path}`;
  const headers = this.forwardHeaders(req);
  const upstream = await fetch(url, {
    method: req.method,
    headers,
    body: req.method !== 'GET' ? JSON.stringify(req.body) : undefined,
  });
  res.status(upstream.status);
  // SSE/流式：逐 chunk 透传，不缓冲
  const reader = upstream.body?.getReader();
  while (reader) {
    const { done, value } = await reader.read();
    if (done) break;
    res.write(value);
  }
  res.end();
}
```

```ts
@Injectable()
export class RemoteUserGuard implements CanActivate {
  canActivate(ctx: ExecutionContext): boolean {
    const req = ctx.switchToHttp().getRequest();
    const userId = req.headers['x-user-id'];
    if (!userId) throw new UnauthorizedException('缺少用户上下文');
    req.user = {
      id: Number(userId),
      username: req.headers['x-user-name'],
      roles: (req.headers['x-user-roles'] as string)?.split(',') ?? [],
    };
    return true;
  }
}
```
